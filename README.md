# Путешествие души — Soul Journey (Итерация 1: сингл-песочница)

Текстовая браузерная стратегия про развитие аэропорта. Полный дизайн — в
`airport-game-design.md` (был передан отдельно). Это рабочий прототип первой
итерации: клеточный мир, экономика тиков, часть каталога построек, счётчик
времени до 10 уровня и сингл-рейтинг.

## Сайт игры: https://g.yourcrew.ru:8443/

## Что уже работает

- Регистрация/вход (логин+пароль, токен-сессия)
- Выбор режима старта (путь A «с нуля» активен; путь B «с воздуха» — заглушка под Итерацию 2)
- Клеточная территория 4×4 с расширением до 8×8 через «Выкупить землю»
- Полный каталог построек из дизайн-документа (доход/тик, XP, требования по уровню)
- Серверный тик раз в минуту — начисление дохода, live-обновление через WebSocket
- Автоматический уровень (1→10) по накопленному XP
- Таймер «время полёта» и сингл-рейтинг (время до 10 уровня), отдельно по пути старта
- Файловое JSON-хранилище (файл `data.json`, создаётся автоматически) — без нативных зависимостей, ставится на любой VPS без сборки

## Что ещё не реализовано (по плану — Итерации 2–4)

- Путь старта B («с воздуха»)
- Самолёты, авиакомпания как механика (сейчас офис авиакомпании — просто здание с доходом)
- Мультиплеер: общий мир, маршруты между игроками, аренда стоянок, торговля, сборы за обслуживание
- Многоклеточные ВПП/терминалы (сейчас каждое здание = 1 клетка, для MVP упрощено)

## Запуск локально

```bash
npm install
npm start
```

Откройте `http://localhost:3000` (или порт из переменной `PORT`).

## Деплой на свой VPS

1. Установите Node.js 18+ на сервере (`node -v` для проверки).
2. Скопируйте папку проекта на сервер (`git clone`/`scp`/`rsync`).
3. `cd airport-game && npm install --production`
4. Запуск через процесс-менеджер, чтобы сервер жил после разрыва SSH-сессии:
   ```bash
   npm install -g pm2
   pm2 start server/index.js --name soul-journey
   pm2 save
   pm2 startup   # чтобы пережил перезагрузку сервера
   ```
5. Порт по умолчанию — 3000. Чтобы отдать игру на 80/443 с доменом и SSL,
   поставьте перед Node.js nginx как реверс-прокси (пример конфига ниже) и
   получите сертификат через `certbot`.

### Пример nginx-конфига (реверс-прокси + WebSocket)

```nginx
server {
    listen 80;
    server_name your-domain.example;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```


### Почему JSON-файл, а не SQLite

Изначально использовался `better-sqlite3`, но это нативный модуль — на части VPS
`npm install` для него требует компиляцию (node-gyp, Python, доступ к
nodejs.org за заголовками), и установка может просто упасть без интернета до
нужных серверов или без build-инструментов. Файловое хранилище работает
гарантированно на любом Node.js без дополнительной настройки. Для MVP и
небольшой нагрузки этого достаточно; при росте — миграция на Postgres/SQLite
делается заменой `server/store.js` без изменения остального кода.

## Экономика ботов-компаний (сингл)

Здания (кроме админздания и вертолётной стоянки — они несъёмные) можно
**продать**, **сдать в аренду через биржу** или **снести**. Боты — пять
виртуальных компаний-игроков:

1. ОАО «Запредел»
2. ЗАО «На пределе»
3. ООО «Выше всех»
4. ООО «Космос»
5. ООО «Сатурн»

**Продать** — разовая выплата 60% от стоимости постройки, доход с клетки
прекращается, здание помечается именем бота. **Можно выкупить обратно** в
любой момент за полную стоимость постройки.

**Снести** — здание пропадает, клетка освобождается, возвращается 30% от
стоимости постройки.

**Сдать в аренду** открывает биржу:
- Сервер сразу показывает 2–3 готовых предложения от случайных ботов
  (цена — случайный множитель 1.3×–2.2× от обычного дохода здания). Можно
  принять любое из них сразу — здание тут же переходит в аренду по этой
  цене.
- Либо можно назначить свою цену и «выставить на биржу» — здание уходит в
  статус ожидания (дохода в это время нет). На каждом следующем тике сервер
  сам решает, согласится ли кто-то из ботов: чем выше цена относительно
  «справедливой» (доход × 1.8), тем ниже шанс. Если никто не соглашается
  несколько тиков подряд — есть шанс, что биржа снимет здание с продажи и
  вернёт его вам. Оба исхода (согласились / отказались) приходят игроку
  уведомлением через WebSocket.
- Пока здание сдано или выставлено на бирже — продать или снести его нельзя,
  сначала нужно вернуть его себе.

Все числа (диапазоны цен, «справедливая» цена, шанс истечения листинга)
настраиваются в `server/gameData.js` → `BOT_ECONOMY`. Цена от клиента при
принятии готового предложения проверяется на сервере (не может быть
произвольной — защита от подделки запроса).

### Старт новой игры

Новый игрок начинает на **уровне 0, без единого здания**, со стартовым
капиталом **10 000 у.е.** Первым делом он строит две обязательные постройки:
**здание администрации** (3 000 у.е., +150 XP) и **вертолётную стоянку**
(2 000 у.е., +150 XP). После обеих накапливается 300 XP — ровно порог
**уровня 1**, с которого открывается остальное дерево построек. Здание
администрации уникально (одно на аэропорт) и после постройки пропадает из
меню; вертолётных стоянок можно строить сколько угодно. Оба этих здания
нельзя снести или продать.

### Приём бортов и оплата за прилёт (Слой 1)

Договоры теперь платят не фиксированную сумму в минуту, а **за каждый прилёт
борта**. Пока действует договор, авиакомпания периодически (примерно раз в 2
игровых часа) присылает борт. Борт садится, если есть свободное место на
стоянке (вертолётная стоянка даёт мест по числу уровня апгрейда: ур.1 = 1 …
ур.5 = 5), приносит оплату и стоит на земле 30 минут, занимая место, затем
улетает.

Если свободных мест нет, борт встаёт в очередь. Он ждёт до 20 минут; если за
это время место не освободилось — разворачивается, и аэропорт получает штраф
(двойная оплата за прилёт) и теряет репутацию. Поэтому важно, чтобы мест
хватало на поток бортов от всех договоров.

Диспетчерская вышка задаёт интервал между операциями (потолок пропускной
способности); без вышки действует стартовый интервал. В шапке показывается
занятость стоянки (например «2/3», а в скобках — сколько бортов в очереди).

Свои самолёты пока работают по прежней схеме (через число ВПП) — их
интеграцию в общую пропускную способность сделаем следующим слоем. Все числа
приёма — в `server/gameData.js` → `APRON_ECONOMY` и `CONTRACT_ECONOMY`.

## Договоры с авиакомпаниями (конверт)

Когда аэропорт может принимать борты (на старте достаточно вертолётной
стоянки, дальше — связка вышка + ВПП + терминал), в шапке появляется кнопка
**«✉ Договоры»** с числом новых предложений. Внутри — предложения от
авиакомпаний-ботов и действующие договоры.

Каждое предложение содержит название авиакомпании, оплату в минуту и срок
(в игровых сутках), с кнопками **Принимаю / Подумаю / Отклоняю**. «Принимаю»
заключает договор — авиакомпания платит фиксированную сумму каждую минуту,
пока договор действует (позже оплата станет за каждый прилёт борта).
«Отклоняю» убирает предложение. «Подумаю» откладывает его — оно живёт
дольше, но всё равно со временем истекает. Действующий договор можно
**расторгнуть** досрочно.

Договоры срочные (по истечении исчезают), держать можно сколько угодно
(позже ограничит пропускная способность). Сумма и частота предложений растут
с репутацией и уровнем аэропорта. Все параметры — в `server/gameData.js` →
`CONTRACT_ECONOMY`.

## Содержание аэропорта, долг и банкротство

У аэропорта есть постоянный расход — **«Содержание аэропорта»** (статья
администрации), который списывается каждую минуту и растёт с числом и
уровнем построек. Если аэропорт долго простаивает (сейчас простой = нет
летящих рейсов; позже добавятся договоры и суточный лимит) дольше 5 игровых
часов, содержание увеличивается.

Содержание может увести баланс в минус — это долг. Пока баланс
отрицательный, репутация падает каждую минуту, и капитал в шапке горит
красным. Предел долга («дно») равен суммарной стоимости всех построек
игрока. Как только долг достигает дна — наступает **банкротство**: игра
окончена, показывается экран «Игра окончена. Вы разорены.» с двумя кнопками:
«Начать сначала» (полный сброс аэропорта — уровень 0, стартовые деньги, без
построек, самолётов, названия и АК) и «Удалить аккаунт» (удаляет
пользователя со всеми данными).

Все параметры (базовый расход, доля от стоимости, множитель за апгрейд, порог
и множитель простоя) настраиваются в `server/gameData.js` → `CONFIG`.

## Время строительства и апгрейда

Постройка и улучшение зданий идут не мгновенно, а занимают время. При
постройке здание сразу появляется на клетке в статусе «строится» и пока не
приносит доход, не даёт мест под самолёты и не считается за ВПП; опыт за
постройку начисляется в момент завершения. При апгрейде здание продолжает
работать, но с пониженными показателями (`UPGRADE_WORK_PENALTY`), а новый
уровень включается по завершении. Пока идут работы, действия со зданием
недоступны — нужно дождаться окончания. Статус и остаток времени видны на
клетке (бейдж «СТРОЙКА N» / «АПГРЕЙД N»), в таблице объектов и в окне здания.

Длительность выводится из стоимости здания (дороже — дольше) либо из
явного поля `buildTicks`, если оно задано. Множитель `BUILD_TIME_SCALE` в
`CONFIG` ускоряет все сроки для отладки (сейчас 0.05 — примерно в 20 раз
быстрее); для реального баланса времени его возвращают к 1.

## Название аэропорта и своя авиакомпания

При первом входе игрок вводит название своего аэропорта — оно показывается
в шапке между названием игры и именем игрока.

Собственные самолёты доступны не сразу: сначала нужно создать **свою
авиакомпанию**, а это возможно только с 5 уровня. При достижении 5 уровня
приходит предложение создать АК (принять или отложить). Если отложить — в
шапке появляется кнопка «Создать АК». Пока АК не создана, кнопка «Авиапарк»
видна, но при нажатии просит сначала создать авиакомпанию. После создания АK
(с вводом её названия) открывается покупка и управление самолётами.

## Топливо, склад и поставщики

Каждый рейс расходует топливо. Половина заправляется дома со **склада**
(бесплатно, если на складе есть запас), вторая половина (дозаправка «в пункте
Б») покупается у поставщика по его цене и вычитается из выручки рейса. Если
склад пуст или его нет — всё топливо покупается у поставщика (рейс дороже, но
возможен). Так склад — выгодное вложение, а не жёсткий блокер.

**Топливный склад** имеет вместимость по уровню апгрейда (5000…40000 единиц).
Клик по складу открывает **биржу поставщиков** — пять нефтяных компаний с
разными ценами за единицу топлива (ИП «Дам бенза» — самое дешёвое,
АО «НефтьПродукт» — самое дорогое). Игрок выбирает поставщика и пополняет
склад; стоимость пополнения = объём × цена поставщика. Текущий запас
показан в шапке (статистика «Топливо») и в окне склада (шкала).

Запас нужно периодически пополнять — это стимул заходить в игру. Все числа —
в `server/gameData.js` → `FUEL_ECONOMY` и `FUEL_SUPPLIERS`.

## Самолёты и авиапарк (Итерация 2, ядро)

Три типа самолётов по документу: **Маленький** (только ВВЛ, $200 000,
вместимость 10/20/50 по апгрейду), **Узкофюзеляжный** (ВВЛ+МВЛ, $500 000,
90/150/200) и **Широкофюзеляжный** (ВВЛ+МВЛ, $1 000 000, 120/250/400). У
каждого есть тип линий (ВВЛ или ВВЛ+МВЛ), объём баков (в часах полёта) и
уровень апгрейда, повышающий вместимость.

**Ресурс под списание:** самолёт летает, пока суммарный доход от него не
достигнет двойной цены покупки. После этого он списывается («СПИСАН»), больше
не летает (в том числе в авто-режиме) и его можно только продать. В карточке
самолёта есть шкала «до списания». Списание считается по накопленной
положительной выручке.

Механика приобретения (покупка/лизинг), рейсов, ремонта и авто-режима —

Открывается кнопкой **«Авиапарк»** в шапке. Самолёты не занимают клетки —
им нужны **места**: стоянка (перрон) даёт 1 место, ангар — от 1 до 4 в
зависимости от уровня апгрейда. Всего мест = сумма по всем стоянкам и
ангарам; больше самолётов, чем мест, завести нельзя.

Три типа самолётов (малый / средний / большой) отличаются ценой,
вместимостью, длительностью рейса, расходом топлива и штрафами. Каждый можно
**купить** навсегда или взять в **лизинг** (разовый депозит + платёж каждый
тик). Лизинговый самолёт можно **выкупить** в собственность по остаточной
цене с учётом износа (чем больше налетал — тем дешевле выкуп). Собственный
самолёт можно **продать** по цене перепродажи (тоже с учётом износа);
лизинговый — вернуть без выплаты.

**Рейсы:** для взлёта и посадки нужна свободная **ВПП** — число одновременно
летящих самолётов не может превышать число ВПП. Отправленный в рейс самолёт
занят N тиков, затем возвращается с выручкой: загрузка (55–100% вместимости)
× тариф за пассажира − топливо. Есть шанс задержки (+50% топлива). За каждый
рейс растёт износ (до 60%).

**Ожидание посадки:** если самолёт вернулся, а свободной ВПП нет — он кружит
в ожидании, и каждый тик капает штраф: топливо (списывается из денег) и
падение репутации (недовольство пассажиров). Как только ВПП освобождается —
садится и приносит выручку. Поэтому важно держать баланс между числом
самолётов, стоянок и ВПП.

**Авто-режим:** у каждого самолёта есть кнопка авто-рейсов. Включённый
самолёт сервер сам отправляет в рейс, как только тот свободен и есть
свободная ВПП — не нужно жать «В рейс» вручную.

**Поломки и ремонт:** после рейса, чем выше износ, тем выше шанс поломки
(самолёт переходит в статус «сломан» и не летает). Чинить можно двумя
способами: **быстро за деньги** (кнопка «Ремонт», мгновенно, цена растёт с
износом) или **бесплатно ангаром** — ангар постепенно снижает износ стоящих
самолётов каждый тик (сколько самолётов за тик — зависит от суммарной
ёмкости ангаров) и возвращает сломанные в строй.

Все параметры (цены, вместимость, топливо, износ, штрафы, шанс поломки,
стоимость ремонта) настраиваются в `server/gameData.js` → `AIRCRAFT_TYPES` и
`AIRCRAFT_ECONOMY`.

Дальнейшие проходы (ещё не сделаны): разные маршруты/дальность рейсов, путь
старта B, мультиплеер.

## Интерфейс игрока

Игровой экран состоит из двух панелей: слева — широкая **таблица «Мои
объекты»** (столбцы Объект / Описание / Действие), где в столбце «Объект»
показывается миниатюра-фото постройки (та же картинка, что и на клетке —
своя иконка → скин из Галереи → эмодзи), справа — меню-каталог доступных
построек. Сетка территории вынесена в отдельную модалку, открывается
кнопкой **«Территория а/п»** в шапке: там клик по пустой клетке показывает
меню построек с кнопкой «Построить здесь», а клик по занятой — модалку
управления зданием. В таблицу попадают все купленные игроком объекты;
столбец «Действие» показывает текстом доход и репутацию за тик (с учётом
уровня апгрейда) либо статус — «Аренда: +N у.е./тик», «Продано боту», «На
бирже». Клик по строке таблицы открывает ту же модалку управления зданием,
что и клик по клетке.

Вёрстка адаптивная под три размера экрана:
- **Монитор** (>1024px) — три панели в ряд.
- **Планшет** (≤1024px) — поле клеток сверху на всю ширину, под ним таблица
  и постройки в два столбца.
- **Телефон** (≤700px) — всё в один столбец: поле, затем таблица, затем
  постройки; шапка со статами, модалки и кнопки подстроены под узкий экран и
  нажатие пальцем.

## Апгрейды зданий и Галерея

У каждого здания в игре есть свой уровень апгрейда (не путать с уровнем
аэропорта!) — прокачивается индивидуально, за деньги, прямо из модалки
здания в игре кнопкой «Улучшить». Апгрейд поднимает доход и репутацию
постройки (+30% за каждый уровень выше первого), стоимость растёт с каждым
уровнем (`cost × 0.6 × уровень`).

- Здание администрации и вертолётная стоянка — до **5 уровней**.
- Все остальные здания — до **3 уровней**.
- Апгрейдить можно, только пока здание в собственности (не в аренде и не
  продано боту).
- Все числа настраиваются в `server/gameData.js` → `UPGRADE_ECONOMY`, а
  максимальный уровень — в поле `maxUpgradeLevel` каждого здания в каталоге.

**Раздел «Объекты»** (`/admin.html` → вкладка «Объекты») — настройка типов
зданий, применяется **глобально у всех игроков**. Сверху форма: выбор
здания из списка, редактирование его названия, описания, размера шрифта и
цвета текста подписи. Ниже — таблица всех объектов (Объект / Описание /
Действие) как на главной странице игрока, где столбец «Описание» можно
править прямо в ячейке (сохраняется по Enter или потере фокуса). Описание,
как название и стиль текста, — глобальное для типа здания.

**Галерея** (`/admin.html` → вкладка «Галерея») — только картинки уровней:

Картинка клетки в игре — фиксированный размер **124×124 пикселя**, занимает
всю квадратную область клетки (`object-fit: cover`), название — отдельной
строкой строго под картинкой. Приоритет отображения иконки: своя иконка
клетки, заданная админом персонально этому игроку (см. раздел про
кастомизацию клеток выше) → глобальный скин из Галереи для (тип, уровень) →
стандартный эмодзи. Приоритет названия: персональное имя клетки → глобальное
переименование из Галереи → стандартное название из каталога.

При вводе размера шрифта в Галерее можно писать как `18px`, так и просто
`18` — сервер сам подставит `px` (голое число без единицы — невалидный CSS,
браузер его молча игнорирует, из-за чего раньше размер визуально не
менялся).

Загруженные картинки хранятся в `public/uploads/gallery/` (PNG/JPEG/GIF/WEBP/SVG,
до 5MB на файл).

## Мобильная адаптация

Игровой экран и админ-панель адаптированы под мобильные экраны (медиа-запросы
в `public/style.css` и `public/admin.css`, брейкпоинты 800px / 640px / 400px):

- Шапка со статами переходит в сетку 2×2, лишний текст бренда скрывается на
  самых узких экранах.
- Территория и панель построек встают друг под другом вместо двух колонок.
- Модалки (постройка, биржа, рейтинг, медиатека) раскрываются на всю ширину
  экрана снизу, как нижний лист (bottom sheet).
- Сетка клеток (124×124 каждая) не сжимается — вместо этого прокручивается
  по горизонтали свайпом, чтобы картинки не искажались на маленьком экране.
- В админке панель игроков/категорий Галереи встаёт над деталями вместо
  колонки сбоку, поля форм — на всю ширину.

## Админ-панель

Доступна по адресу `/admin.html` (например `http://your-server:3000/admin.html`).
Вход — теми же логином/паролем, что и в игре; доступ получают только аккаунты
с `isAdmin: true`. По умолчанию единственный админ — `SoulJourney` (см. ниже).

Что умеет:

- **Данные игрока** — деньги, XP, уровень и размер сетки редактируются в
  одной форме с единой кнопкой **«Сохранить»** (уровень и XP синхронизируются
  между собой; при уменьшении сетки здания за её пределами сносятся).
  Кнопка **«Сбросить к последнему»** возвращает поля к сохранённым значениям,
  а **«Сбросить в исходное»** полностью обнуляет игрока — уровень 0,
  10 000 у.е., без зданий, сетка 4×4, как сразу после регистрации.
- **Клик по любой клетке** на территории игрока открывает редактор:
  назначить здание на пустую клетку или заменить существующее (бесплатно,
  без проверки уровня/денег), снять здание принудительно (не глядя на
  статус аренды/продажи), задать **свою иконку** (эмодзи или прямая ссылка
  на картинку) и **своё название** для этой конкретной клетки — игрок увидит
  это в игре вместо стандартных.
- **Галерея** — глобальная медиатека и апгрейды зданий, см. раздел выше.
- **Баны**: 5 часов / 1 день / навсегда / разбан. Забаненный аккаунт не
  может залогиниться и мгновенно теряет доступ к игровому API (в том числе
  активная сессия — WebSocket-соединение сразу разрывается). Администратора
  забанить нельзя.

Все данные меняются напрямую в `data.json`, никаких дополнительных таблиц —
админка работает поверх того же файлового хранилища, что и игра.

## Аккаунт-демонстрация SoulJourney

При каждом старте сервер автоматически создаёт (если его ещё нет) аккаунт с
максимальными статами — удобно, чтобы сразу показать полностью отстроенный
аэропорт, не проходя игру с нуля.

- Логин: `SoulJourney`
- Пароль: `ggg777ggg`
- Деньги: 999 999 999, уровень 10, репутация 999 999, вся территория 8×8
  застроена всеми зданиями из каталога.
- Также назначен **администратором** — имеет доступ к `/admin.html`.

Реализовано пока только для сингла (путь A) — это единственный режим, который
уже есть в коде. Когда появится путь B и мультиплеер, такого же
демонстрационного пользователя нужно будет завести и там.

⚠️ Логин/пароль захардкожены в `server/seed.js` и видны в исходниках. Это
нормально, пока проект живёт только у тебя на сервере. Если когда-нибудь
откроешь код другим людям (публичный репозиторий, доступ третьим лицам) —
смени пароль через `reset-password.js` или вырежи вызов `ensureSuperuser()`
из `server/index.js`.

## Сброс пароля игрока

В MVP нет восстановления пароля через email (нет почтового сервиса). Если
игрок забыл пароль, сбросьте его прямо на сервере:

```bash
cd airport-game
node server/scripts/reset-password.js <логин> <новый_пароль>
```

Пример:
```bash
node server/scripts/reset-password.js soultest MyNewPass123
```

Пароль должен быть от 4 символов. Скрипт не требует остановки сервера — можно
выполнять прямо во время работы игры, изменения применятся при следующем логине.

## Настройка баланса

Все цифры баланса (стартовый капитал, стоимость построек, доход за тик,
пороги XP на уровень, стоимость расширения земли) вынесены в
`server/gameData.js` — правьте их без изменения логики сервера.

Длина тика задаётся в `CONFIG.TICK_MS` (по умолчанию 60 000 мс = 1 минута).
